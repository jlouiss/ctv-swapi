# Proximity-triggered prefetch instead of an explicit "Load more" tile

Category lists and search results both load incrementally (10 items/page from swapi.dev). The next page prefetches silently in the background once focus reaches roughly two tiles before the end of the currently loaded set, so the new tiles are already present by the time focus would actually reach them — no explicit "Load more" control, no visible loading gap at the point of arrival. `useCategoryList` and `useSearch` each expose the same `hasMore`/`loadMore` shape so `ListScreen` can drive both off one proximity trigger without caring which is active.

We initially considered an explicit focusable "Load more" tile, reasoning that auto-loading would fight `norigin-spatial-navigation`'s focus model by inserting new tiles mid-navigation. That reasoning had it backwards: CTV platforms (Netflix, Disney+, Prime Video, YouTube TV) and their design guidelines (Android TV/Google TV, Roku) standardize on proximity-based prefetch specifically because remote input makes every extra OK-press costly, and prefetching *ahead of* arrival — rather than *on* arrival — avoids the focus-shift problem: nothing new appears until focus is already about to move onto it.
